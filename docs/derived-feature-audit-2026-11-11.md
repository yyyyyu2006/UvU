# 二改功能检查与优化清单 · 2026-11-11

本轮已修复截图、视频中确认的 7 处问题。后续清单包含现有实现的限制、需要真实设备验证的风险及可选增强，**不等于另外发现了 53 个已复现的 bug**。未借本轮检查重写 1900 版代码或全面更换 UI。

## 1. 检查范围与结论

- 对照本地 `1900版uwu`，清点 `js/`、`css/`、`services/` 的 184 个应用源码、样式与配置文件：101 个新增、44 个有差异、39 个一致，忽略换行差异。这是当前整体二改与基线的清点，44 个差异文件并非本轮全部修改。第三方 vendor、依赖、运行目录 `.runtime/`、个人数据和测试产物不算自研源码。前期宽口径统计的 200 个文件包含 16 个运行目录文件，最终排除。
- 逐模块检查新增入口、保存位置、身份绑定、异步取消、开关、上下文使用和错误处理；另读同工作区的 SillyTavern 桥接插件。模块覆盖见下文；这是静态审查和有针对性的运行检查，不能证明所有输入、所有手机均无缺陷。
- 本轮应用修改集中在通知投递、二改面板 DOM 整理及对应样式。`chat_ai.js` 只增加通知投递判重；未修改聊天提示词、历史截取、世界书计划、provider 请求或响应解析。
- 本轮没有修改 1900 原始样式文件、状态栏模板、音乐 Apple Music 页面、导出 ID Card 绘制、已经发送的文件卡片与一起听邀请卡片。
- 审查外部实现使用 GitHub 插件，实际读取 12 个项目的 13 个源文件。只能借鉴适合当前框架的机制；不引入其聊天提示词，不进行框架迁移。

### 保持的兼容边界

```text
chat.history.slice(-chat.maxMemory)
  → filterHistoryForAI()
  → 原有提示词与上下文组装
  → 原有 provider 请求与响应解析
```

下文如涉及后续记忆、工具或环境增强，必须由原有独立开关控制；关闭、失败或取消时回到现有行为。任何改变召回、生成或注入的建议需要单独实施和验收。本报告没有把这些建议全部开启。
