# 分类备份与保存优化

在主页打开「数据管理」，使用「导出分类」或「导入分类」。两种操作在当前页面分别记住勾选范围，刷新后恢复全选。可独立选择聊天记录、角色设定、世界书、用户设定、壁纸与外观、字体、基础设置。只分享角色时可只选角色设定；迁移一个新设备的全部常规数据时保留全选。

全选沿用原有备份范围：包括全部聊天存档、记忆及设置；相册、工坊历史等大图缓存仍不在此备份范围。分类备份不会删除源设备的数据，导入时只处理勾选分类。已有角色按 ID 合并，单独导入角色设定保留本地聊天，单独导入聊天保留本地人设和额外存档；世界书、表情集合沿用原来的整体替换规则。

导出可选 `.ee` 压缩备份或 `.json` 通用备份。`.ee` 仍为 gzip 压缩的原有 JSON 数据结构，未新增加密或版本门槛。旧版带 `modules` 和旧版无 `modules` 包装的 JSON 都能导入。浏览器不支持解压 `.ee` 时会明确提示，可升级浏览器或从原设备导出 JSON；格式支持不等于不同应用版本支持所有新增字段。

分类导入先校验并准备本次要变更的数据，再在同一 IndexedDB 事务中写入，成功后才替换内存数据。失败不会先把界面数据改掉；不再为了回滚克隆整份数据库。导出角色设定也不再先复制整段聊天再删除。JSON 仍需要完整解析，因此超大单文件仍有内存需求，分类导出有助于降低该需求，并非流式解析。

普通保存继续同步活动存档，并在事务内逐条对照数据库内容，仅写入发生变化的记录。例如给一个角色发消息时，不再重写全部其他角色、世界书、表情和设置。直接原地修改消息也能识别，失败后下一次保存会重新比较，不依赖可能失效的缓存基线。比较仍会读取历史内容，并不承诺所有设备上的保存耗时都降低；角色和群聊一次只读取一条，避免为比较长期保留整库副本。

完整聊天渲染复用一次生成的过滤规则，并顺序维护前一条有效消息，避免逐条反复扫描历史。分页、长按、引用、选择、已总结原文折叠及滚动行为保留。没有引入 DOM 虚拟化，也没有修改移动端模糊效果。

本轮没有修改聊天、通话、世界书注入、日记、自动总结或思维链提示词。分类备份仍按用户勾选保存或恢复这些数据，不会自行改写提示词内容。

开发验证：安装 Node.js 24 或更高版本，运行 `npm ci`，再运行 `npm test`。新增测试使用与页面相同版本的 Dexie 和内存 IndexedDB 验证事务失败回滚、重试、连续保存、活动存档同步及分类恢复。这些开发依赖不加入页面运行或部署流程。
