# 1900 兼容与角色身份

## 基线

兼容是保护原版流程，不是把全部二改回退。比较本次函数、调用和实际请求再处理差异。tests/legacy_1900_compat.test.cjs 读取 UVU_1900_ROOT，必须指向真实原版目录。npm run test:1900 严格检查文件完整性，缺失即失败；普通开发仅可通过 UVU_ALLOW_MISSING_1900=1 显式跳过，并报告1900未验证。

原版目录由 `UVU_1900_ROOT` 或当前机器核验的配置提供，不能把个人绝对路径写进共享测试。原版已有问题按 [审查要求](audit.md) 归类；已有明确修复授权只作用于对应问题，不能理解为允许重写原版流程。

## 回复与上下文

新增选项关闭时保护此路径：

```text
chat.history.slice(-chat.maxMemory)
  → filterHistoryForAI()
  → 原版提示词与上下文组装
  → 原版 provider 请求／响应解析
```

- 核对提示词文本、世界书筛选／排序、收藏记忆、历史范围、顺序和角色；UI 任务不要求改写这些路径。
- 自动总结隐藏、向量、环境、MCP、酒馆记忆只在相应选项启用后介入，检查关闭、默认与旧数据迁移状态。世界书按用户2026-11-22决定恢复1900四类位置及depth排序；旧高级规则不再执行。
- 不恢复高级激活计划、关键词/概率筛选或历史深度插入。Token和诊断只读原版静态选择，不能反过来驱动请求。
- 导演 API 与总结是独立阶段，不为它们改写普通聊天基础提示词；控制标签不进入朗读正文。非本次原版优化留待用户判断。
- 不为解决某个提供商响应问题，静默改动历史末尾角色、预填充、世界书深度或预设。先核对实际请求、状态码、响应类型与脱敏返回样本，区分配置错误和解析缺陷。流式、非流式、空正文、工具返回、截断和取消分别验证。
- 思考面板只能显示模型接口实际返回且明确用于展示的 reasoning／thinking 字段或文本；不得编造、拿普通回复假充，或声称可恢复未返回的隐藏思考。没有返回时明确暂无内容，不为此改写主提示词。

## 桥接与异步

- 启用、配对、可达、绑定和剧情模式分别判断；配对 Token 不代表启用或进入线下。
- 关闭互通后停止检查／注入；超时、鉴权和网络失败不冒充可信线下状态而中止普通回复。
- 有效绑定会话的明确线下状态只影响该会话，其他角色、存档和新聊天不继承。
- 任务启动时固定角色ID、存档ID、来源和会话／批次ID；完成后核对身份与版本，结果不能写到新的 currentChatId。
- 名字只用于显示，不能作为唯一绑定键；检查重名、改名和切换。

## 剧情与记忆

- 按楼层保留来源，支持整层审核、全选与编辑。正文识别用明确标签及可配置回退，不声称覆盖所有预设。
- 导入只产生待审内容；审核后按当前流程写入对应角色的 memoryJournals／日记。正文与总结分开，失败不静默替换原文。
- 选摘要时复用第三人称摘要总结能力，审核摘要后才作后续记忆。不混入状态栏、代码、小剧场与未批准内容。
- 写入和注入是两个状态，保留收藏、权限与开关；关闭注入不删除已批准日记。
- 按来源、楼层或批次去重；刷新／重试不重复写入。刷新固定绑定目标，不回退主存档或其他聊天。

对本次路径检查关闭、启用、失败／超时、角色／存档切换。有限样本不能推出全部原版行为或全部手机兼容。

## 其他二改模块的约束

| 模块 | 必须保留的行为 |
|---|---|
| 备忘录／向量记忆 | 依据真实上下文记录事实，保留来源、审核、直接删除和更正能力；去重与冲突处理不串角色；只有启用且允许的记忆参与后续对话 |
| 动态评论 | user、char、NPC 使用稳定身份和明确权限，不凭昵称判断；AI 不擅自扮演 user 发言，char／NPC 互动与回复正确关联原评论 |
| MCP | 工具列表／数量缓存、检测时间、当前连接状态分开保存与展示；重开不能把已保存列表无故重置为 0，缓存也不冒充实时连通；工具调用仍受开关和权限约束 |
| MiniMax | API 设置继承原面板；语音、导演和播放分阶段处理，失败不阻断普通文字回复，切角色后的旧音频不接入新会话 |
| 音乐／一起听 | 登录、歌单元数据、音源可用性分别判断；切歌不结束会话，一起听浮窗仅在聊天界面显示并服从手动关闭；保留列表／单曲／随机、播完续播、歌单改名等已有行为 |
| 备份／导入 | 保留 `.ee` 兼容和可见导入入口；先完整校验再写入，失败不覆盖当前存档；分块／回滚按现有框架处理，不悄悄改成不兼容 txt |
| 文件／PNG 角色卡 | 私聊目标固定，分享内容与 char 可读范围一致；PNG 外观保持 ID card、透明圆角和作者署名，保留角色／可选世界书的导入导出兼容 |
| 日历／经期 | user／char 记录分别归属；区分日历估计、实际检测、观测提示，证据不足或矛盾时显示未知，不硬给精确排卵日；不把预测包装成诊断 |
| 后台／通知 | 页面恢复、权限、后台限制和用户开关分别处理；不重复通知，不用持续音频等手段夸大或保证系统永不挂起 |

这些是现有功能的兼容检查点，不代表本轮已经检查或实现。具体状态仍以当前代码、用户最新要求和验证结果为准。
