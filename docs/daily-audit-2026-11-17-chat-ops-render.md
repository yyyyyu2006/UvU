## ISSUE-MEDIT-20261117-01 · P2 · 二改异步解析会让取消的旧保存重新生效

- 最危险的问题：保存消息等待状态栏解析时，只比较消息 ID，不能分辨关闭后再次编辑同一条消息，或同一面板提交的新保存。已确认，属于功能问题，不是新 Security 漏洞评级。
- 可能后果：旧任务先完成会把旧草稿写进聊天和 IndexedDB；新保存随后因原消息已变化而作废。用户取消、重开同一消息后的旧任务还可能关闭新编辑框。
- 位置：修复前 `chat_ops.js` 689–691、718–723；修复后 694–696、723–728。普通编辑、调试编辑、手动新增、取消和重复保存均须使旧解析任务失效。
- 来源：`e8d4b737` 引入 `await prepareStatusRegexJobs` 与异步后校验；真实 1900 对应保存使用同步 `new RegExp().exec()`，写消息前没有这段等待。本次只对照相关旧源码，没有声称完整旧站实机验收。
- 局部修复：增加编辑操作序号；打开、取消及新保存时递增，在解析结束及共享历史写入前核对。保留现有身份、存档、消息内容校验与回滚机制。
