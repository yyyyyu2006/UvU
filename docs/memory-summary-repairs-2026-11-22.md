# 自动总结与向量检索：首批修复

日期：2026-11-22，Asia/Shanghai。起点：`a0abe24`，在 `test` 实施。本文记录首批补丁，完整25项方案尚未全部完成；main 发布仍等用户确认。本次未调用真实模型、未读取个人聊天或密钥。

## 本批用户可见变化

- 自动总结只生成和保存，不再全量自动引用、替代历史或折叠气泡。原文仍按原历史条数与过滤规则读取，保留 `maxMemory=0` 的既有修复。
- 有效且已提交／审核的自动总结可以手动收藏，按1900原收藏位置读取；默认不收藏，也不自动开启向量。来源编辑、撤回或权限撤销后不能继续读取失效总结，手动合并的来源快照也要校验。
- 自动生成父总结不会撤掉子总结的收藏。手动合并的明确替代关系仍按既有规则处理。
- 已有 `useMemory`、`hideSummarized`、`contextInjectionOptIn` 字段保留供备份和代码回退，新版只读投影统一禁用旧执行路径，非活动存档和导入数据同样适用。不批量改写旧数据，不偷偷收藏旧总结。旧开关用户打开设置时看到升级提示，保存成功后记录知悉版本。
- 主回复不再等待一次新的自动总结；保留已有回复后调度和每存档串行任务。停止主回复不连带取消独立总结。
- 总结质量审核增加否定、人物归属、过去／现在、未完成／取消约定、多代压缩提醒。它们只是人工核对线索，不自动判真、不改写总结或原文。
- 聊天式重排只接受完整JSON编号排列或整串纯逗号编号，拒绝解释数字、日期、重复、缺失和越界编号。失败保留检索顺序。专用接口拒绝重复／非法编号；遗漏候选不伪造分数，启用最低分时排除无分项。
- 单候选启用专用重排最低分时也实际评分；无最低分时可跳过，诊断明确标记。余弦、词匹配、检索融合分和重排分分别记录，不称为事实正确率。
- 查询整理保留原查询，再最多增加一路改写；按已知姓名、明确日期、异地／网恋／取消等词及否定标记作保守检查。失败沿用原查询；不能保证本地检查能识别所有语义漂移。
- 新增可选整轮预算，默认关闭：排队、正文准备、查询整理、查询嵌入、索引补建及重排共用耗时／请求上限。手动建库仍走原建库预算。超时与用户取消分别报告，检索失败可继续主聊天；已成功保存的索引缓存不等于本轮已注入。JS同步计算不能被计时器强行抢占。
