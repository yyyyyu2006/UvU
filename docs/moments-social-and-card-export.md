# 动态互动与 PNG 角色卡导出方案

日期：2026-11-08。动态互动与 PNG 角色卡导出已实现。

## 一、动态互动：入口与使用

1. 打开当前角色的「动态」，点击顶部「动态互动设置」。
2. 开启「动态互动」，保存。默认关闭，关闭时继续使用已有动态界面。
3. 在「人物」中添加 NPC，填写姓名、人设与口吻、关系、知道的事情；按需要选择「认识我」和可互动的 NPC 范围。
4. 也可以点击「从人设提取人物」，审核候选列表后添加。提取结果不会直接成为正式人物。
5. 评论动态，或点击某条评论回复。系统按准确的评论 ID 连接回复，不按显示姓名猜测对象。
6. 开启自动互动后，发送评论会启动独立生成。动态菜单也有「生成互动」；生成期间可以停止。刷新只更新显示。
7. 动态菜单中的「整理为记忆」打开摘要审核，生成或手工编辑第三人称文字，再点击「审核并保存」。只有确认的内容才写入现有日记记忆。

### 已实现的范围

| 板块 | 当前行为 |
| --- | --- |
| 身份 | user、char、NPC 使用分类型 ID；重名不会合并；旧记录姓名有歧义时保留未绑定状态 |
| NPC 管理 | 手工添加、修改、停用、删除；从角色人设提取草稿并审核 |
| 知情范围 | NPC 只接收自己的资料、公开动态评论及明确共享的信息；不会发送主角/用户私人人设和私聊历史 |
| 评论互动 | char 回复 user/NPC；NPC 回复 user/char/NPC；每位发言者独立请求，允许选择不发言 |
| 回复关系 | 按动态和评论 ID 精确连接；拒绝不存在目标、前向引用和连续回复自己；删除保留关系占位 |
| 发布 | user 发布；char/NPC 生成草稿经确认后发布；支持配图与可见范围 |
| 操作 | 点赞、评论展开、自己的评论编辑、评论删除、动态编辑/删除、人物资料 |
| 通知 | 显示新的相关互动，进入后标记已读；阅读通知不会让在途生成失效 |
| 草稿 | 按角色和存档保存评论草稿；同一标签页重载可恢复；界面重绘保留滚动位置 |
| 记忆 | 第三人称摘要预览、编辑、审核保存；同一动态重复保存更新已有记录 |
| 请求控制 | 每次 1–8 位发言者，默认最多 4 位；间隔可调，每条动态每天最多 20 批；相同触发去重 |
| 异常处理 | 停止/超时、目标编辑或删除、切换存档后丢弃过期结果；失败保存撤销本次改动并保留同时收到的新内容 |
| 渲染 | 评论使用文本节点；原始 HTML 不能变成可执行内容；新样式限定在新增界面 |
| 备份 | 原有备份路径增加新字段校验；不更换原备份格式 |

### 与既有聊天的边界

- 普通私聊使用既有提示词和请求组装；没有修改 `chat_ai_prompt.js`。
- 关闭动态互动时，不发送新增的社交请求。开启时，新评论由独立模块处理，避免原有解析器重复生成。
- user 的评论/点赞按既有方式产生可感知的事件记录；NPC 和 char 的新评论不会逐条塞入私聊历史。
- 审核保存的摘要进入既有 `memoryJournals`，标记收藏，后续按现有记忆规则使用。
- 新动态保存成功后才尝试触发互动；异步保存前后校验原角色、存档和历史引用。
- 没有改写原版动态 CSS 或用户自定义美化。

### 验证边界

单元测试使用模拟模型响应，浏览器测试使用真实请求构建器及本地替代响应，未消耗用户真实 API 额度。覆盖身份隔离、错误目标、知识隔离、请求上限、取消、存档竞争、失败回滚、摘要审批、备份校验、草稿重载，以及 320/390/768px 布局。真实模型的自然度、多人长时间使用和大型动态列表性能仍需后续体验验证。

## 二、PNG 角色卡：研究结论

本次核对了以下主仓库的规范/源码，访问日期为 2026-11-08：

- Character Card V2：`https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md`
- Character Card V3：`https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md`
- SillyTavern PNG 读写：`https://github.com/SillyTavern/SillyTavern/blob/release/src/character-card-parser.js`

已直接读取上述文件的 raw 源码。SillyTavern 文件顶部仍有旧的「不支持 ccv3」注释，但实际写入/读取代码已有 V3 分支，应以实际代码和规范为准。

PNG 角色卡是在正常图片内部写入结构化数据，不是把人设文字截成一张图。V2 使用 `tEXt` 数据块的 `chara` 关键字，内容为 UTF-8 JSON 的 Base64；V3 使用 `ccv3`。同时存在时，支持 V3 的读取器优先读取 V3。重写时清理旧的角色数据块，避免一张图保留两份不一致的人设。

标准角色卡只有一个 `character_book`，其中可以有多个条目。因此选中多本 UvU 世界书时，应将所选内容汇总到一个标准嵌入书，同时在 `extensions.uvu` 中记录来源、分组及需要保留的原始配置。

### 当前实现与兼容边界

- PNG 导出写入 V2 `chara`；导入优先读取 V3 `ccv3`，不存在时读取 V2。优先块损坏时明确失败，不悄悄使用旧副本。
- 新导入的卡片在 `characterCardSource` 保存经过筛选的标准字段与未知扩展。人设仍沿用 `description/persona`，没有新增提示词注入。旧角色过去已经丢失的卡片字段不能自动还原。
- 中文、Emoji、换行、占位符及标准卡的独立人设字段可以往返；V3 专属资产、V3 写入和 NPC 配置导出不在首版范围内。
- 世界书支持关键词、顺序、位置、概率及原规则保留，重导入后高级规则默认关闭。静态书导出为常驻条目，避免被未启用的高级规则误停用。分组在 UvU 之间保留。
- 部分平台插入位置和规则并不等价。特殊位置在生成后提示确认；尚未在实际 SillyTavern/TauriTavern 中执行导入，不能据本地往返测试标注为完整兼容。

## 三、面板布局

入口位于当前私聊「聊天设置」右上角的下载图标，默认使用当前角色。

1. 顶部：标题「导出角色卡」，右侧简短 PNG 格式标记。
2. 角色区：居中显示 3:4 证件卡预览，下面一行放角色名与「更换头像」。黑色标题带、左侧头像和装饰条码、右侧资料、下方签名与淡蓝印章沿用确认的草稿。
3. 卡面资料：就近折叠生日、身份、国籍三个选填字段。生日、国籍不猜测，空值在卡上显示横线；身份默认「角色」。只写入本次导出的公开卡片资料，不改写人设。
4. 人设区：一行「角色人设」，点击展开查看；正文不可因导出操作改写。
5. 世界书区：标题和全选同一行；每项一行勾选框、书名和条目数，下面的「查看内容」就近展开。
6. 更多设置：折叠放置作者、版本等低频字段。
7. 底部：左侧「人设 + N 本世界书」，右侧紧凑胶囊按钮「导出 PNG」。

上述布局已接入当前角色的真实保存数据。支持分组和逐条勾选、全选/取消、展开正文、上传本地封面；「导出 PNG」生成并下载含角色数据的真实图片。

样式使用白底、浅灰分组、少量浅蓝，24px 面板圆角，14px 正文，8px 倍数间距。减少常驻说明；兼容性问题只在导出前出现具体提示。

## 四、实施清单与完成范围

### P0：数据与兼容

1. **独立导出模块。** 新建 `character_card_export.js`，不接入聊天生成流程。打开面板时获取角色、人设、封面、所选世界书的只读快照；异步处理结束后核对角色/存档，防止导出错人。
2. **标准字段映射。** `realName → name`，`persona → description`；确实存在的 personality、scenario、开场白、示例对话映射到对应字段，没有则留空。保留 `{{char}}`、`{{user}}`、中文、Emoji、换行。全局提示词不复制到卡片的 `system_prompt`。
3. **原始信息保留。** 给后续导入增加原始卡片数据容器，保留未知 `extensions`；导出时以当前编辑字段覆盖对应原字段，不伪造曾被丢弃的数据。
4. **世界书选择。** 默认列出当前角色已绑定条目及分组；支持全选/取消、逐项查看、明确选择附带内容。未选书和其他角色的私有书不混入。
5. **世界书转换。** 标准字段包括 content、keys、secondary_keys、enabled、constant、insertion_order、position；平台专属概率、深度、角色、匹配规则放入兼容扩展。缺省值依据实际原规则转换，不将原先常驻的书无意改为永不触发。
6. **合并与来源。** 多本书汇入一个 `character_book.entries`；保持确定的顺序并生成卡内唯一条目 ID；`extensions.uvu` 保存来源书名、分组和原规则，导入时重新分配本地 ID，避免覆盖现有角色和书。
7. **导出范围。** 角色人设为必选，世界书可选。聊天记录、用户人设、记忆日记、配对信息、API 密钥均不写入。若未来增加 NPC 配置，作为单独明确选择的 UvU 扩展处理。

### P1：PNG 读写与面板

8. **图片处理。** 角色头像或手动选择的 PNG/JPEG/WebP 居中裁切到证件照区域，生成固定白底 900×1200 PNG。远程图片跨域失败时提供本地上传替代。无头像时使用名字首字。UvU 自己生成的证件卡重导入时提取 300×400 头像区域，避免聊天头像和再次导出嵌套整张卡片；外来角色卡保持原来的整图头像处理。
9. **可靠写入。** 核验 PNG 签名、块边界和长度，使用经过验证的 CRC 实现；在 IEND 前写入数据。先完成画布处理，再写元数据，因为重新经画布导出会丢失附加数据块。
10. **格式选择。** 首版稳定输出 V2 `chara`；后续可提供 V3 双格式，V2/V3 必须由同一快照生成并同步。旧的同名块清除，其他合法图片块保留。不能只改扩展名假装转换成功。
11. **导出 UI。** 实现上述面板，绑定真实数据、全选/数量联动、展开预览、封面选择和作者版本。处理空世界书、缺失绑定、长书名、长人设和窄屏；移动端检查触控和保存文件行为。
12. **明确失败。** 图片读取、跨域、PNG 编码、数据过大、下载失败分别提示；失败不替换人设、不修改书、不输出没有角色数据的普通图片作为成功结果。禁止重复点击并支持取消耗时操作。

### P2：往返验证与分享

13. **独立读回校验。** 用与写入不同路径的解析器读回最终 Blob，逐项比对角色名、人设、所选世界书内容和规则。测试多字节字符、大数据块、损坏 CRC、截断文件、重复块和 V2/V3 冲突。
14. **扩充导入兼容。** 在不改变既有默认注入行为的前提下增加 V3 优先读取和边界检查；兼容导入保留未支持规则，给出具体提示。分别在实际 SillyTavern 和 TauriTavern 版本测试后再标注已验证兼容。
15. **使用与隐私说明。** 导出前可查看包含内容；分享时建议发送原图/文件，图片重压缩可能移除内嵌数据。角色卡分享与原 `.ee` 整机备份保持独立。全部在浏览器本地完成，不需要部署新后端。

### 使用步骤

1. 进入需要分享的角色私聊，打开「聊天设置」，先保存本次人设修改，再点击右上角下载图标。
2. 查看证件式卡面，按需点击「更换头像」，展开「卡面资料」填写生日、身份、国籍；展开人设核对文字。未填的资料不会被推断。条码为装饰图形，签名为角色名的字体效果。
3. 勾选附带的配套世界书，也可以全部取消，只导出角色。展开分组可按条目选择和查看正文。
4. 「更多设置」可填写作者与版本；「分享说明」说明导出范围和原图分享方式。
5. 点击「导出 PNG」。生成期间可以取消；切换角色、存档或修改设定后需要重新打开面板。
6. 将下载文件作为原图或文件分享。接收方使用角色卡导入入口导入 PNG，不要把压缩后的聊天图片当作原文件。

### 验证结果

- 单元测试覆盖二进制 CRC、截断、重复块、V3 优先、大小限制、Unicode、数据隔离、静态/高级规则、旧 JSON 文本世界书、分组往返和保存失败回滚。
- 真实 Chrome 浏览器验证了下载并独立提取 PNG 元数据、使用实际 UvU 导入器重导入、本地封面、无世界书导出、远程图片失败、取消生成、未保存设定拦截、处理中切换角色与 320/390/768px 布局。
- 导入保存失败仅撤销本次新建的角色和世界书，不移除同时增加的其他记录；复用已有世界书不改变它的原分组。
- 文件最大 32 MiB，角色元数据最大 8 MiB，封面输入最大 16 MiB；导出图片固定 900×1200px。输入宽高不得超过 16384px，总像素不得超过 64M。导出只保留证件照区域的裁切图，不能用它恢复原照片被裁掉的部分。
- 未读取用户私聊、用户人设、日记和应用凭据作为导出来源；导入扩展中的已知敏感字段会被筛除。自由文本本身含有隐私时，仍需分享者自行审核。
- 实际 ST/TT 导入、iOS/Android 保存和第三方软件转发后的元数据保留情况仍待实机验证。

### 验收标准

- 选甲角色不会带出乙角色人设/世界书；切换存档不会偷换导出目标。
- 导出后原角色、世界书、历史和全局提示词保持原值。
- 未选中的世界书不存在于 PNG 数据中。
- UvU 重导入得到可用的新角色，已有角色不被覆盖；保留中文和占位符。
- 本地已验证人设和配套世界书读回；酒馆实际导入是后续外部兼容验收项。
- 分享后的文件可在不联网的情况下读出元数据；文件损坏时不给出成功提示。

## 五、后续优先级

V2 本地导出、读回验证、源字段保留和 UvU 重导入已实现。下一步优先实机检查 ST/TT，再考虑 V3 写入与可选 NPC 扩展。动态列表的分页/虚拟化和更细的单条配额可单独迭代，不将其描述为本轮已实现。
