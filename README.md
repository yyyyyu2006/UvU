# UwU / 章鱼喷墨机

这是一个由 HTML、CSS 和 JavaScript 组成的静态网页项目，入口为 `index.html`，可以直接部署到 GitHub Pages，无需安装依赖或运行构建命令。

## 上传到 GitHub

1. 登录 GitHub，创建一个名为 `uwu` 的仓库。使用免费个人账户部署时，选择 **Public**（公开）。
2. 新建空仓库后，点击 **uploading an existing file**；如果仓库已有文件，点击 **Add file → Upload files**。
3. 打开电脑上的 `uwu` 文件夹，把里面的全部文件和 `css`、`js` 文件夹拖入上传区域，保持目录结构。
4. 确认 `index.html` 直接位于仓库根目录，与 `css`、`js` 同级。不要把最外层 `uwu` 文件夹整个上传成一层子目录，也不要只上传 ZIP 压缩包。
5. 填写提交说明，提交到 `main` 分支。

上传后的结构应类似：

```text
index.html
community_detail.html
css/
js/
contacts.css
more_menu.css
style.css
manifest.json
sw.js
.nojekyll
README.md
```

## 开启 GitHub Pages

1. 在仓库中打开 **Settings → Pages**。
2. 在 **Build and deployment** 中，把 **Source** 设为 **Deploy from a branch**。
3. **Branch** 选择 `main`，目录选择 **/ (root)**，点击 **Save**。如果实际上传到其他分支，则选择那个分支。
4. 等待部署完成，刷新 Pages 设置页，点击 **Visit site** 查看网站。

如果仓库名为 `uwu`，默认网站地址为：

```text
https://你的GitHub用户名.github.io/uwu/
```

这是地址格式示例，实际链接以 Pages 设置页显示的地址为准。

## 后续更新

将修改后的文件上传并提交到发布分支，GitHub Pages 会自动重新部署。需要保留 `css` 和 `js` 的原有目录结构。

网页中的聊天和图片生成等功能仍需在应用设置中配置相应服务；静态网页托管本身不提供这些 API。

## 左滑引用回复

在私聊或群聊中，按住消息向左滑动约 56px 后松手，即可引用该条消息。输入框上方会显示发送者和消息内容，输入回复后点击发送即可；发送后的消息会保留引用信息，刷新后仍可查看。也可以沿用长按消息菜单中的 **引用**。

点击引用栏右侧的 **×** 可取消引用，已经输入的草稿会保留。上下滚动、向右滑动、短距离滑动和多选模式不会触发引用；撤回消息和系统提示不能引用。切换聊天或历史存档时会清空待发送的引用。

引用保存完整文字，图片、表情包、语音等显示对应类型提示；发送给 AI 的上下文也包含引用对象和内容，支持 OpenAI 兼容接口及 Gemini。

开发验证（需要 Node.js）：

```sh
node --test tests/home_presets.test.cjs tests/quote_reply.test.cjs
```

## 消息范围多选与分享

私聊和群聊中，长按一条消息 → **多选**（原有“删除”入口也能进入）。未选消息旁会直接显示 **选到这里** 按钮，点击即可选中起点与终点之间的消息，包含两端，支持向上或向下选取；也可继续使用长按菜单。起点取最近一次手动勾选的消息，已有选择会保留，也可以逐条取消。

可先加载更早的消息，再跨分页选择。范围仅包含当前已加载并显示的消息，不自动勾选隐藏思考、未显示系统消息或记忆折叠原文。需要处理折叠原文时，请先显示原楼层。切换聊天或存档不会沿用旧选择。

多选后可点击 **删除已选**、**分享记录** 或 **截图**。分享记录会打开站内角色／群聊选择器，选好接收对象并点击 **发送聊天记录** 后，合并成一张可点击查看的卡片发送到对方当前存档。记录按原顺序保留发送者、时间、正文和引用；本地上传图片可在详情查看，其他媒体保留类型提示。取消转发保留当前选择。接收角色后续正常回复时能读取转发正文，转发本身不额外调用 API。原有截图模式也支持“选到这里”。

开发验证：`node --test --test-isolation=none tests/*.test.cjs`。

## 分享与导入主页预设

在主页打开 **自定义 → 个性化设置 → 主页预设**。

1. 调整好桌面布局、壁纸、图标和小组件，填写预设名称。
2. 按需勾选“同时导出当前字体、字号和全局 CSS”，点击 **导出主页预设**。
3. 将下载的 `主页预设-名称.json` 分享给其他人。
4. 接收者在同一入口点击 **导入主页预设**，选择 JSON 文件，查看信息并确认应用。返回主页即可看到效果，刷新后仍会保留。

预设包含主页分页及顺序、日夜模式、自定义图标、壁纸、主页签名、桌面上使用的小组件实例与对应模板，以及小组件的图片和文字。不会包含聊天记录、角色卡、世界书、API 地址或密钥，也不会打包未使用的组件库。组件内手动填写的内容和代码会随预设分享，请自行检查其中的个人信息。

上传到应用的本地图片会以内嵌数据保存；勾选外观时，当前使用的本地字体也会一并打包。网络图片和网络字体仍依赖原始链接。预设文件上限为 50MB。

导入会替换当前桌面布局和桌面小组件，建议先导出自己的主页备份。原有组件模板库会保留，同 ID 的不同模板会自动分配新 ID。包含字体和全局 CSS 的预设会同时影响其他页面的外观。小组件支持自定义 HTML/JavaScript，仅应导入信任来源的预设。

格式为 `uwu-home-preset`，版本为 `1`。普通数据备份或单个小组件 JSON 不能作为主页预设导入。

开发验证（需要 Node.js）：

```sh
node --test tests/home_presets.test.cjs
```

## 自动记忆与大总结

聊天 → 日记（群聊为“总结”）→ **自动记忆 / 大总结设置**。默认关闭自动整理。可配置保留楼层、旧楼层阈值、每批条数、目标字数、大总结阈值与篇幅，以及主 / 副 API、独立记忆 API 和完整自定义提示词。提示词留空时沿用原有日记与合并精简规则。

成功总结的楼层自动跳过并续接。大总结严格按同层篇数触发，例如 6 篇小总结才生成大总结，手动整理也遵守该阈值。还可指定 1–700 层等范围，填写份数后一次启动分批总结；每份分别调用 API、成功即保存，中途可停止或失败后续接。

成功保存的记忆会替代来源原文进入后续上下文，大总结替代下层摘要，完整聊天记录仍保留，可显示原楼层或暂停记忆恢复原文。详见 [使用与恢复说明](docs/auto-memory.md)。

开发验证：`node --test --test-isolation=none tests/*.test.cjs`。
