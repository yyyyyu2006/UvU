# UvU music app approved design

User approved the earlier twenty-point implementation checklist, added QQ Music login alongside NetEase, requested a new home icon without replacing Tavern, and supplied a white library/mini-player reference.

## Architecture

- Independent `uvu-music-screen` and `app-uvu-music`, leaving `app-placeholder`/Tavern and customized old music entries intact.
- White/light-gray library, generous spacing, album artwork, compact icon controls, green listening accent from reference, 24px tool surfaces, three tabs, bottom mini-player and expanded now-playing sheet. Styles scoped to new UI/card only.
- Music gateway in `services/music-gateway/`, Node built-ins and one pinned external provider engine installed by an explicit setup script. HTTPS production endpoint configured in app; Pages cannot host backend. No automatic cloud deployment and no public anonymous demo carrying accounts.
- Upstream research candidate: `jimmyshuixin/Music-api` revision `4d83862b063b31af3eab1d823cfc7ff584609234`, MIT; NetEase and QQ QR capabilities checked against source. Use individual provider instances per user/account, no shared cookies. Credentials remain gateway-side; gateway token stays outside backup.
- Frontend browser globals: `UvUMusic` (model/API/library/player), `UvUMusicUI` (screen), `UvUMusicChat` (cards/sharing/invites). Parent owns integration of existing files.
- Plain music message content contains bounded song facts and selected lyrics; no song means no request/prompt changes. No acoustic-understanding claim. New music message metadata validated and secrets stripped from portable state.
- Listening session is bound to char/archive. Invitation is a user message; acceptance/rejection uses explicit bounded per-invite action controls attached to the ordinary response, never keyword guessing. No main prompt modification when inactive.

## Shared interfaces

Track: `{provider:'netease'|'qq'|'local',id,title,artists:string[],album,cover,duration:number(seconds),pageUrl?,localId?,availability?:'unknown'|'full'|'preview'|'unavailable'}`. Portable tracks never hold cookies, signed media URLs or audio bytes. Optional transient local input URL accepted by player only.

Gateway `/v1`: `POST /session -> {token}`, authenticated Bearer subsequent routes; `GET /health -> {ok,providers:[...]}`; `GET /accounts -> {accounts:[{provider,loggedIn,user?:{id,name,avatar}}]}`; `POST /accounts/:provider/qr -> {id,image,url,expiresAt}`; `GET /accounts/:provider/qr/:id -> {status:'waiting'|'scanned'|'authorized'|'expired',user?}`; `DELETE /accounts/:provider`; `GET /search?providers=netease,qq&q=...&page=1 -> {tracks,errors,hasMore}`; `GET /track/:provider/:id/stream -> {url,availability,expiresAt?,message?}`; `GET /track/:provider/:id/lyrics -> {lyric,translation?}`; `GET /accounts/:provider/playlists -> {playlists:[{id,name,cover,count}]}`; `GET /playlist/:provider/:id?page=1 -> {tracks,hasMore}`. Bounded responses, timeouts, no full cookies/QR polling credentials exposed. Failed platform retains other search results. No download, DRM bypass or arbitrary URL proxy.

`UvUMusic`: normalizeTrack(raw), key(track), settings(), saveSettings(patch), connect(), request(path,{method,body,signal}), accounts(), createQR(provider), pollQR(provider,id), logout(provider), search(q,providers,page,signal), playlists(provider), playlist(provider,id,page), lyrics(track,signal), importLocal(file), library(), toggleFavorite(track), addPlaylist(name), addToPlaylist(id,track), removeFromPlaylist(id,key), clearRecent(), player.

`player`: snapshot() -> `{track,queue,index,playing,phase,position,duration,mode,error,sleepAt}`, subscribe(fn)->unsubscribe, play(track,queue?), toggle(), next(), previous(), seek(seconds), setMode('order'|'shuffle'|'one'), enqueue(track,next?), remove(index), setSleep(minutes), stop(), suspendVoice()->resume callback. `music-state` CustomEvent on changes for UI. Latest playback intent wins. Local IndexedDB audio excluded from backup. Queue persists metadata; refresh never autoplays.

UI calls `UvUMusicChat.share(track,{invite:false})` (current chat, or select character if launched outside private chat), `listen(track, binding)` only after acceptance; chat helper can use `player` events.

## Acceptance and limits

- Unit tests: provider/account/session isolation; QR expired/foreign session; unsafe URL denial; partial platform failure; playback race/permission failures; queue; local persistence rollback; portable redaction; archive-bound invites; ordinary 1900 request unchanged.
- Browser: 320/390/768px app/card, no overflow, real controls, fixture audio, QR accounts, search pagination, lyrics, queue, invitations and different-chat safety. Physical iOS/Android and real account approval/VIP rights require real devices/users.
- External API behavior can drift. Document source revision and setup, do not claim live logins were verified if only fixtures used. Server code is deliverable; online Pages requires a deployed HTTPS gateway before real platform login/search.
