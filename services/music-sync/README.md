# 独立音乐同步服务

此服务供两台真实设备同步播放控制和用户明确发送的歌单。它不读取音乐平台账号、不下载或转发音频。现有的角色「一起听」保持独立。

使用 Node.js 22 或更新版本，无需 npm 依赖：

```sh
node services/music-sync/server.cjs
```

默认监听 `127.0.0.1:3211`。打开小手机的「音乐扩展 → 跨设备」，手动开启扩展，填写 `http://127.0.0.1:3211`。第一台创建房间，将房间码和邀请口令交给第二台；第二台加入。房主手动发送当前播放，或明确开启持续发布。来宾手动对齐，或明确开启跟随。双方分别在本机解析自己有权播放的音源，没有权限时会提示失败，不会借用房主凭据。

本机双客户端可以用两个浏览器窗口。自动验证使用两个独立客户端连接真实 HTTP 服务：

```sh
node --test tests/music_sync.test.cjs
```

跨设备使用自己的 HTTPS 反向代理，设置环境变量（按操作系统语法设置）：`HOST=127.0.0.1`、`PORT=3211`、`ALLOWED_ORIGINS=https://你的网页域名`。代理转发到 `127.0.0.1:3211`。若需容器监听可明确设置 `HOST=0.0.0.0`。无需付费服务，也不会自动部署。HTTPS 页面无法直接使用远程 HTTP 服务；手机的 localhost 指手机自身。

房间最多两人；房主拥有播放控制权，来宾可读取状态。两人均可明确发送歌单，使用 `expectedRevision` 检查版本，旧版本写入返回 409，必须重新预览。歌单合并先展示本机、远端、共同基线的差异；同时编辑或删除冲突须用户选择。房主离开立即关闭房间；来宾离开释放其位置。房间固定两小时过期；服务重启后房间和暂存歌单消失。需要保留的歌单先合并到各自本机，或下载离线快照。

客户端每秒校准服务时钟并读取进度，断网后按 2/4/8 秒间隔重试，恢复时保留原角色和令牌。令牌只在客户端内存中，刷新页面需重新创建/加入。关闭面板会停止轮询并离开。房间服务只保留严格筛选的歌曲公开标识和文字元数据，拒绝任意音源 URL、cookie 和 token 字段进入同步内容。邀请口令及房间令牌是房间访问凭据，请仅交给实际参与者。

服务限制每 IP 每分钟 500 请求、最多 100 房间、JSON 最大 2 MB。浏览器只允许配置的精确来源及本机来源。此版本为单进程服务，房间在内存中，不能直接水平扩容。跨公网提供给多人使用时，需部署者自己维护 HTTPS、访问准入和资源容量。

接口版本为 1：`POST /v1/rooms`、`POST /v1/rooms/:id/join`、`GET /state`、`POST /control`、`GET/POST /playlists`、`POST /leave`。创建/加入以外的房间接口用 `Authorization: Bearer ...`；查询地址不得携带参数；所有响应禁止缓存。服务不发送外部请求。
