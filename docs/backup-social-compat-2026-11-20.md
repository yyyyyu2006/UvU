# 备份动态兼容排查

用户提供四张手机截图，确认备份只在手机，未直接检查个人备份或密钥。本批基于 test 61404f9，main 的相关备份/动态代码相同；不能把构造数据的原因当作用户文件的最终诊断。

## 已确认的问题

1. 数据管理导出会调用动态校验。一个旧存档失败即可阻止整份导出，且未勾选完整性校验时只显示“导出失败，请重试”。构造旧存档已复现。
2. 原版动态/评论使用 `moment_${Date.now()}` / `comment_${Date.now()}` 编号。同一毫秒内的多条旧记录可能重号。二改把“开启过动态设置的所有旧数据”统一当作新格式严格检查，造成兼容冲突。构造含两个同编号动态、两条同编号评论的存档已复现；新增测试在修改前失败。
3. 多种动态错误被统一改写成“有效的动态人物与评论关系”，原来的具体原因和字段丢失；弹出提示也会排在其他通知后。本批区分列表、编号、人物、可见范围、次数、批次、点赞、回复目标、评论状态与设置错误，并将具体路径保留在页面状态区。

截图里的 `characters[5].archives[0].data.momentsSocial` 表示校验指向第六个角色的第一个存档，并不证明是人物配置本身损坏。未检查原文件，不能确认重号、断开的回复目标或其他字段中的哪一种导致此次失败。

- 新格式的重复身份、有歧义的回复目标、无效设置和其他格式错误仍拒绝导入，写入前校验与事务回滚保留。
- 导出遇到可识别的动态数据错误，保留其原始字段并下载备份，在 `backupManifest.warnings` 和页面明确提示导入仍可能受限；不声称已修复原数据或保证这份救援备份可直接恢复。
