# 自动记忆与大总结

入口：聊天 → 日记（群聊为“总结”）→ 自动记忆 / 大总结设置。私聊、群聊及各自存档独立保存设置和记忆。默认关闭自动整理，不会因升级直接调用 API。

## 触发与楼层

一条有效的用户或角色消息算一楼。系统消息、思考、撤回、状态更新和手动禁用上下文的消息不计入整理范围。先保留最近 K 楼，再计算剩余尚未总结的旧楼层；旧楼层达到阈值 T 后，按时间从旧到新，最多处理 B 条。

默认 K=20、T=30、B=30，意味着累计 50 条有效消息时，首次整理最早 30 条，保留最近 20 条。小总结目标约 800 字；生效记忆积累到 6 篇，最多合并 6 篇，生成目标约 1500 字的大总结。大总结也能参与以后合并。目标字数通过提示词约束，不截断模型正文。

在进入聊天、发送消息、请求 AI 回复前及回复结束后检查条件。请求回复前会等待本聊天已有的整理任务，以便本次请求就使用摘要。一次检查最多生成一篇楼层记忆和一篇大总结，避免导入大量旧聊天后无限调用。积压历史可通过“保存并立即整理一批”逐批处理；该按钮忽略阈值，仍保留最近楼层。

自动整理仅在网页运行时执行，关闭页面后没有服务器后台任务。API 超时上限 90 秒；自动调用失败后冷却一分钟，手动操作可以重试。

## API 与提示词

可以选择主 API、副 API，或沿用 API 应用中“回忆日记”的路由。副 API 的地址、密钥、模型在原有 API 应用中配置；强制选择副 API 时，配置缺失会报错，不回退主 API。支持现有 OpenAI 兼容和 Gemini 请求方式。

两种提示词留空时，直接使用原有日记和“合并精简”提示词。私聊沿用现有日记风格、角色信息和世界书；群聊沿用原有群聊总结规则。填写完整自定义提示词后，不再附加默认写作风格，聊天或摘要资料会自动提供。还可以填写补充要求。自定义提示词明确指定格式或篇幅时，以其为先。模型是否完全满足语义和字数要求仍取决于所选模型。

默认格式必须有完整且非空的 title/content XML 标签；自定义提示词允许直接输出正文或 JSON 等文本。空结果、缺失标签和请求失败均不启用原文覆盖。不会为了满足字数设定强行截断正文。

## 记忆注入与恢复

总结保存成功后自动进入后续上下文，无需收藏。大总结替代其来源摘要，避免同时注入上下层记忆。手动收藏的普通日记仍按原逻辑进入上下文；自动摘要的收藏按钮禁用，因为注入由自动记忆设置控制。文字聊天和通话背景均使用生效记忆。

完整 history 始终保留。聊天界面默认折叠已总结楼层，可点击折叠提示或日记页面的“显示 / 折叠原楼层”查看。显示原文只改变界面，AI 仍使用记忆。

- 关闭“开启自动整理”：停止以后自动调用，已有记忆继续使用。
- 关闭“使用自动记忆”：暂停自动调用和自动记忆注入，原文恢复进入上下文；原有上下文条数上限仍生效。
- 删除大总结：恢复尚有效的下层摘要。删除小总结：解除其原楼层覆盖，相关上层摘要也会失效。
- 编辑、撤回或删除来源消息：来源指纹验证失效，对应自动记忆停止注入，恢复可用原楼层。
- 编辑摘要正文：该摘要继续可用，但依赖旧正文的上层摘要失效。

先排除有效摘要覆盖的原文，再应用聊天原有上下文条数上限。总结过程使用独立任务锁，避免同一聊天和存档的重复请求；切换存档、修改来源或改变设置时，未完成结果会被放弃。保存使用先草稿后提交的方式，失败不激活覆盖。

## 实现参考

查阅了 [Horae](https://github.com/SenriYuki/SillyTavern-Horae)、[记忆表格](https://github.com/Irena86-08/SillyTavern-Memory-Table) 和 [柏宝书·月夜来信分支](https://github.com/ansdojaods/ST-BaiBai-Book-Tsukiyo) 的公开说明，参考自动摘要、分层压缩、副 API、可追溯来源与避免重复注入的思路。本功能适配本项目的数据与日记体系，不依赖安装上述插件；不包含向量检索、NPC 台账或表格编辑器。

## 验证

运行：`node --test --test-isolation=none tests/*.test.cjs`。新增测试覆盖阈值与保留、层级压缩与恢复、API 路由与提示词、并发去重、持久化失败、来源变化与切换存档。浏览器测试使用独立测试数据、假密钥和模拟 API，不调用用户真实收费接口。
