# 源码逐行审查与修复要求

## 先区分任务

“检查／列清单／先不要改”保持只读；“按清单开始修复”允许在已确认范围内实施，分模块、分阶段验证。“继续”接上当前记录，不从头重复扫描，也不扩大到已排除的功能。全仓逐行审查不等于检查语法或只跑测试。

安全任务读取 [Codex Security 路由](tooling.md) 和相应官方技能；普通功能、UI、维护性检查使用 Agent Skills。用户直接要求“全量审查／架构审查／全量架构审查”时，按宿主约定调用 code-quality-workflow，保留只读边界；合并其结论而非替代 Codex Security。

## 覆盖怎样算数

1. 固定本次仓库、分支、提交和工作区差异；用 `rg --files` 配合 Git 跟踪／忽略规则枚举范围。把前端、服务、桥接、测试、部署和文档分组，不漏掉根目录脚本与子目录。兄弟酒馆项目只在授权范围内纳入。
2. `.git`、依赖安装目录、输出和外部副本默认单列排除；用户明确点名的文件仍纳入。图片等非文本检查引用与可用性，不称逐行读代码。第三方／生成文件标明检查方式，依赖漏洞检查不能代替自研源码审阅。
3. 对自己承担的逐行源码审阅，在既有项目质量审查记录中标明路径、版本或文件哈希、已读行段、结论和待核验项。长文件分段连续读取；截断输出后补读，只有所有行段读完并理解入口与调用关系才记“已逐行审阅”。
4. 记录待审、部分审阅、完整源码审阅、运行未验、已复现、修复待验、验证通过和排除原因；源码审阅完整不等于运行已验。报告已审／总数、剩余路径和实际缺口，不以“读过文件名／关键词命中／测试经过”计完整覆盖。
5. Codex Security 内部的覆盖、发现与结果使用原生规范产物，不另建插件阶段清单。项目质量报告可链接这些产物，并如实记录额外的全文件源码阅读范围，不能据此改写插件原生状态。
6. 续审核对版本：未变化文件可沿用明确证据；变更文件及受影响调用链重新检查。不能沿用历史上的 9、37、322 等数量当作今天的现状。

## 每个模块检查什么

| 方向 | 重点 |
|---|---|
| 隐藏缺陷与边界 | 空值、错误类型、损坏／旧数据、重复 ID、空列表、长文本、跨月跨年、越界和取消 |
| 异步与生命周期 | 切角色／存档／路由、任务晚到、重复监听、刷新恢复、销毁清理、重试与幂等 |
| 原版兼容 | 提示词、历史范围、角色顺序、回复顺序、世界书插入、流式／非流式、重生成与停止 |
| 持久化与备份 | 校验后事务写入、失败回滚、容量不足、迁移兼容、导入导出往返和目标归属 |
| 网络与外部服务 | 超时／中断、HTTP 错误、响应形状、错误缓存、会话恢复、取消及失败后的状态 |
| 安全与凭据 | 鉴权、越权、路径访问、服务端外连、敏感数据暴露；追踪输入到实际危险操作的可达路径 |
| 硬编码秘密 | API key、Token、密码、Cookie、私钥及日志／测试夹具；报告只给脱敏位置，公开示例值不误报为真实密钥 |
| 性能 | 无界集合／请求／循环、全文重复嵌入、主线程阻塞、资源泄漏、音频与图片 URL 释放 |
| 维护和扩展 | 重复实现、全局耦合、隐藏顺序依赖、散落覆盖、无版本数据和职责混杂；只修本次必要范围 |
| 异常与提示 | 错误被吞、成功假象、泄露敏感响应、提示无下一步；取消与故障不能混为同一状态 |
| UI 与交互 | 真实 DOM／样式、遮挡和点击命中、长按与点击冲突、间距／对齐、焦点／滚动和短屏可达 |

只从源码怀疑的项标“待验证”，有复现或明确路径才标“已确认”。没有攻击者可控输入或可达路径时，不把一般质量问题夸大成漏洞。

## 原版与二改必须分开

使用用户提供的真实 1900 目录比较相关实现，记录证据，不凭目录名或旧报告归因。分类为“1900 已有”“二改引入”“二改放大原有问题”“来源未确定”。基线缺失或文件不同不能证明是原版缺陷，也不能报兼容通过。

原版已有问题、用户暂缓项继续列出影响和建议，默认不动；核对用户后续是否已明确授权修复该项。消息脚本执行等暂缓点不得借“安全最佳实践”自动全局重写。修复二改问题时，不顺带改提示词和美化。

## 发现的输出格式

按实际危险程度排序，安全等级与功能优先级分开解释。每项保留用户指定结构：

```text
- 最危险的问题：[编号／优先级] 具体问题；原版／二改归属；已确认／待验证
- 可能导致的后果：出现条件、实际影响和影响范围
- 具体出问题的位置：当前版本、文件路径、准确行号及调用关系
- 推荐修改方式：局部改法、保留行为、取舍和验证方法
- 修改后的代码示例：最小建议片段；尚未实施时明确“建议，未写入”
```

复杂问题补来源、复现步骤、反证、证据边界和遗留项。用户要完整清单时不能只给最严重的几项；结构确实不合理时直接说明原因。代码示例是建议，不代表已经修复。正式安全报告由 Codex Security 生成，用户可读清单不能替代其原生结论。

## 修复顺序与验收

先处理有证据的数据丢失、身份串用和安全边界破坏，再处理主要功能故障，随后 UI／交互、性能与维护性；同级按影响面与复现概率排序。按模块做最小改动，用原触发样本验证失败前／成功后，并检查正常输入、关闭开关和切换目标。

沿用已有测试；对实质行为补回归，不为排版文字或低影响可逆改动写镜像实现的测试。失败时查明是产品、测试、环境还是外部服务，不删断言、不静默跳过、不用简化页面截图冒充真实页面。通过所需检查后停止重复测试，继续下一模块。

每阶段列出已修、验证结果、未修及原因、下一步；发布按 [验证与交付](verification.md)。测试通过只证明所覆盖的条件，不承诺“没有任何 bug”或“所有环境安全”。
