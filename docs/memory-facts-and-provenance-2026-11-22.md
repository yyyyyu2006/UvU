## 实现与入口

| 方案 | 本批行为 | 明确边界 |
| --- | --- | --- |
| B01 | 记忆管理 → 阅读记忆 → 查看原文 → 事实标签 / 新旧核对。复制本篇原句，人工确认主体、属性、取值、肯定/否定、事件时期；分别记录记忆创建时间和标签确认时间。 | 不从发送日期猜事件日期，不自动把引用、假设或同名人物当成用户事实。群聊暂保留主体未知；无自动事实抽取。标签仅用于本地核对，不添加到主聊天提示词。 |
| B02 | 比较最近200篇日记中每篇最多20个有效人工标签，以及最近200条可读备忘录；同主体/属性、明确重叠时期且值或极性不同才列建议，单篇最多30对。用户可确认并存、新旧变化或待核实，亦可撤销。 | 未确认/时间未知不硬判冲突，原日记和已审核事实不自动替换、删除或取消收藏。明确记录“新旧变化”只是关系备注，不表示系统已判定哪篇需要停用；需要改原文/收藏时仍走原入口。没有语义矛盾识别保证。 |
| V07 | 来源去重开关开启后，使用消息编号、原手动总结首尾编号、合并关系和有效备忘录来源，在近期历史、收藏、实际组装的向量片段和备忘录间核对完整事实。 | 仅同来源且清洗后完整覆盖才省去重复；独有取消/改期/否定保留。不同来源的相同文本不自动合并，用户收藏仍保留原位置。按来源和逐字覆盖保守处理，没有语义等价判定。关闭开关保留原选择策略。 |
| S07 | 开启“完整问答分批”后，手动范围按完整问答、每批条数和完整提示词输入估算预算重分；新增可选事件起始楼层（逗号分隔），明确指定新事件。 | 份数是目标，实际份数可因问答和预算改变，执行前预览。单组过长拒绝且不请求、不截断；不自动猜小说场景边界。明确起点可由用户指定在一条角色消息之前。最多100批。关闭时保留旧等份规则。 |
| V05 | 向量设置 → 更多 → 检索质量，可开启用户确认别名/作品词；标准名=别名1,别名2，每行一组（最多40组/每组8别名），作品词每行一个（最多80个）。中文词法保留，明确日期格式统一，英文名按完整词匹配。 | 只改可选本地关键词评分，不改嵌入请求原句、不重写角色/提示词，不进行模型自动推断。重名指向多个标准名拒绝保存；已有损坏词表读取时回退原词法。需同时开启关键词混合检索才参与正常检索。默认关闭。 |
| V14 | 新统一入口 `node tests/memory_regression_benchmark.cjs`：12类标注合成问题 × 7策略84组，加9种来源生命周期场景，共93组，输出精确率/召回率/首个正确名次/误引用/Token估算/请求数/本机耗时。 | 只有固定合成向量和模拟重排，不能代表真实模型质量、网络耗时或费用。真实模型评测仍未执行；没有读取私人数据或调用付费模型。 |

标签、关系与来源/角色/存档/用户身份绑定；原文编辑、撤回、隐藏、上下文停用、来源审核撤销后旧标签不再参加核对。表单保存前拒绝过期快照，并行标签写入串行检查；失败仅回滚本次字段，保留并行正文变化，切档后恢复原存档。导入校验新增字段结构和大小，旧备份缺字段继续兼容。删除标签不删除原文；撤销关系不删除事实。
