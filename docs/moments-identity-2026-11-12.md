# 动态评论身份检查与修复

## 已确认的边界

- 新版动态互动按 user / character / npc 加独立 ID 区分人物。生成任务不选择 user，保存评论也拒绝 user；实际用户留言只能由手动评论入口写入。
- 已有 NPC 自动提取只在提示词里说不能提取用户，没有把用户姓名明确传入，也没有过滤结果。模型误提取用户姓名后，草稿可被保存为 NPC；其 ID 仍是 NPC，但显示像用户在说话。测试已复现这个缺口，不代表已拿到用户实际出错存档。
- 普通聊天中的旧版动态解析仍按姓名写评论；新版互动关闭时走旧路径。为保护 1900 的流程，本次不改该路径，也不改普通聊天提示词。

## 本次修复

- 自动提取 NPC 时明确主角色与用户的姓名、类型和 ID，不添加用户私聊历史或私人人设。
- 过滤自动提取结果中的用户、主角色、已有 NPC、重复名字和 user / char 占位符；比较时统一全半角、大小写并去掉空白。
- 评论请求明确列出用户身份；返回内容只允许 action、content、replyToCommentId。模型返回作者或身份字段时拒绝整批，不让其改写发言者。原代码已由程序固定作者，本次进一步收紧输入格式。
- 不删除旧评论，不改用户手工配置的同名 NPC；真实同名人物继续按各自 ID 区分。
- 不尝试根据“我”等正文词语判定作者，避免误删角色的正常第一人称发言。没有声称能完全阻止模型在语义上模仿用户。

## 验证

- 新增测试覆盖用户被误提取、空白不同的名字、已有 NPC 与重复建议、模型夹带身份字段、同名 NPC 回复真实用户。
- 测试使用隔离数据与模拟 API；未读取个人存档或调用真实收费接口。
- UI 与四张参考图只作风格分析，本次不修改样式或面板布局。
