# 自动记忆与大总结

入口：聊天 → 日记（群聊为“总结”）→ 自动记忆 / 大总结设置。私聊、群聊及各自存档独立保存设置和记忆。默认关闭自动整理，不会因升级直接调用 API。

## 触发与楼层

一条有效的用户或角色消息算一楼。系统消息、思考、撤回、状态更新和手动禁用上下文的消息不计入整理范围。先保留最近 K 楼，再计算剩余尚未总结的旧楼层；旧楼层达到阈值 T 后，按时间从旧到新，最多处理 B 条。

默认 K=20、T=30、B=30，意味着累计 50 条有效消息时，首次整理最早 30 条，保留最近 20 条。小总结目标约 800 字；同层生效记忆积累到 6 篇，最多合并 6 篇，生成目标约 1500 字的大总结。6 篇小总结产生一篇大总结，6 篇大总结才进一步压缩；不同层级不混计，已被合并的摘要不重复计数。每次合并数量不能低于触发阈值。目标字数通过提示词约束，不截断模型正文。

在进入聊天、发送消息、请求 AI 回复前及回复结束后检查条件。请求回复前会等待本聊天已有的整理任务，以便本次请求就使用摘要。一次检查最多生成一篇楼层记忆和一篇大总结，避免导入大量旧聊天后无限调用。积压历史可通过“保存并立即整理一批”逐批处理；该按钮仅忽略旧楼层触发阈值，仍保留最近楼层，绝不绕过大总结篇数阈值。

已成功总结的原消息会按 ID 与内容指纹跳过，刷新页面后继续生效。例如已覆盖第 1–150 层，下次从第 151 层后的未总结消息继续；若此前手动总结了不连续范围，会先处理更早的未覆盖消息。状态栏显示覆盖数量、最末覆盖楼层和下一条未总结楼层。

## 指定范围批量总结

在同一设置窗口填写起始楼层、结束楼层和分份数量，预览实际分配后点击“保存并总结指定范围”。编号与原有手动日记一致，按完整聊天记录从 1 开始，含首尾；系统、撤回等无效消息仍占编号，但不会发给总结模型。

例如 1–700 层分成 7 份，在都是有效且未总结消息时，每份 100 条，一次启动后依次请求 7 篇小总结。大总结阈值设为 6 时，第 6 篇后再请求一次大总结，合计 8 次 API 调用。此功能按份顺序请求，避免一次发送全部长历史；明确指定范围会包含最近楼层，不受“保留最近楼层”限制。

已覆盖楼层自动跳过，剩余楼层再尽量均分。每份成功即保存，中途失败或点击“停止整理”时，成功结果保留，未完成部分不隐藏；可再次启动相同范围续接，不会重复总结成功的来源。允许 1–100 份，每份最多 2000 条，仍需按模型上下文长度选择合理分份。

自动整理仅在网页运行时执行，关闭页面后没有服务器后台任务。API 超时上限 90 秒；自动调用失败后冷却一分钟，手动操作可以重试。

## API 与提示词

可以选择主 API、API 应用中的副 API、沿用 API 应用中“日记 / 记忆总结”的路由，或下方独立记忆 API。原有 journal 路由标识保持兼容。强制选择副 API 或独立记忆 API 时，配置缺失会报错，不回退主 API。支持现有 OpenAI 兼容和 Gemini 请求方式。

独立记忆 API 可以直接在本窗口填写类型、地址、密钥与模型，并拉取模型列表；它专供自动记忆与大总结使用，不改变聊天主 API。接口配置全局共用，选择哪条路由和总结规则仍按聊天与存档保存。配置保存在本机，完整备份或勾选设置的数据备份会包含它，分享主页预设不会包含。原有手动日记继续使用 API 应用的日记路由。

两种提示词留空时，直接使用原有日记和“合并精简”提示词。私聊沿用现有日记风格、角色信息和世界书；群聊沿用原有群聊总结规则。填写完整自定义提示词后，不再附加默认写作风格，聊天或摘要资料会自动提供。还可以填写补充要求。自定义提示词明确指定格式或篇幅时，以其为先。模型是否完全满足语义和字数要求仍取决于所选模型。

默认格式必须有完整且非空的 title/content XML 标签；自定义提示词允许直接输出正文或 JSON 等文本。空结果、缺失标签和请求失败均不启用原文覆盖。不会为了满足字数设定强行截断正文。

## 记忆注入与恢复

总结保存成功后自动进入后续上下文，无需收藏。大总结替代其来源摘要，避免同时注入上下层记忆。手动收藏的普通日记仍按原逻辑进入上下文；自动摘要的收藏按钮禁用，因为注入由自动记忆设置控制。文字聊天和通话背景均使用生效记忆。

完整 history 始终保留。聊天界面默认折叠已总结楼层，可点击折叠提示或日记页面的“显示 / 折叠原楼层”查看。显示原文只改变界面，AI 仍使用记忆。

- 关闭“开启自动整理”：停止以后自动调用，已有记忆继续使用。
- 关闭“使用自动记忆”：暂停自动调用和自动记忆注入，原文恢复进入上下文；原有上下文条数上限仍生效。
- 删除大总结：恢复尚有效的下层摘要。删除小总结：解除其原楼层覆盖，相关上层摘要也会失效。
- 编辑、撤回或删除来源消息：来源指纹验证失效，对应自动记忆停止注入，恢复可用原楼层。
- 编辑摘要正文：该摘要继续可用，但依赖旧正文的上层摘要失效。

先排除有效摘要覆盖的原文，再应用聊天原有上下文条数上限。总结过程使用独立任务锁，避免同一聊天和存档的重复请求；切换存档、修改来源或改变设置、API 配置时，未完成结果会被放弃。保存使用先草稿后提交的方式，失败不激活覆盖。刷新折叠状态会保留已加载的聊天分页，流式回复和消息多选期间延后刷新，避免中断操作。

## 向量检索与接口诊断（2026-11-03）

向量检索仍是单独开关，使用独立向量API，不改变原有日记、总结和合并提示词。聊天请求前，把有效记忆和保留范围之外的旧剧情转换为派生索引；原消息、思维链和状态栏源数据不改写。长记忆继续按段落／句子分块并少量重叠，相关片段按原总结聚合、相邻片段合并去重后再注入。检索失败继续沿用原有记忆注入机制。

嵌入兼容OpenAI的embeddings和Gemini的embedContent／batchEmbedContents。接口地址可以填主机、带版本的基础地址或完整embeddings路径，显式的v1、v2和代理前缀会保留；Gemini不会重复拼接v1beta或models。API响应需返回有效、非零且维度一致的向量；批量结果按index还原顺序。

嵌入批量可设1–16条。已有配置默认保留单条；新配置默认4条，不支持数组input的服务可改为1。成功分块按内容及模型指纹复用，失败时保留已完成的索引供下次继续。批量减少请求往返，不保证降低token计费；不自动进行付费重试。

重排可选“专用Rerank接口”和“聊天模型排序”。专用模型调用rerank端点，以query、documents和模型名发送，按数值相关度排序；聊天排序保留旧方式和原提示词。重排地址和密钥可单独填写，留空沿用嵌入地址和密钥。旧配置按已有模型名兼容选择，可手动切换类型。重排失败保留嵌入相似度结果，不丢弃已经召回的剧情。

“测试向量接口”会发送测试文本，若开启重排也测试重排。该测试由用户点击发起，可能产生少量API用量。设置页显示最近一次测试或检索的失败阶段、HTTP状态、超时／网络提示，不显示密钥、请求正文或上游错误正文。浏览器网络失败无法仅凭代码区分网络、地址和服务端CORS设置，需要结合接口自测判断。超时可设1–120秒，默认30秒；用户取消会传递到正在读取的请求。
