# 记忆优化第三批：阈值建议与失效分块清理

2026-11-22，Asia/Shanghai；起点 `072f326`。用户本轮“继续”，沿用已经明确的剩余方案，按项目规则交付 test；上一批直接 main 的授权不延续。

## 本批实现

### V09：按当前模型预览阈值建议

- 入口：聊天内“记忆管理 → 检索 → 本轮检索诊断 → 阈值建议预览”。使用当前角色、当前存档和当前配置的模型。
- 明确点击请求后才用已有有效索引采样，不补建缺失分块，不整理查询、不写入聊天、不改变正常检索结果。采样在阈值和最终 TopK 过滤之前，避免只看已命中的高分资料；每次按余弦最多取20个来源，最多10种问题。只代表这个窗口，不表示覆盖所有记忆。
- 展开资料，人工标记相关/不相关，至少两种问题、两条相关和两条不相关，才计算建议。对0–1、步长0.01的候选阈值比较已标样本的误命中、漏掉与F1（兼顾精确率和查全率的综合分）；同分时优先较少误命中、离原设置更近的值。不自动写入参数，没有“已达到模型真实准确率”的保证。
- 可单独勾选专用重排评分。聊天式编号排序没有可标定分数，拒绝冒用；缺少分数、非有限值或超出现有控件范围，不给虚假建议。重排建议先按当前余弦/关键词门槛限定样本，不同时偷偷调整两个阶段。
- 余弦、关键词放行、RRF名次和专用重排分开解释；混合检索下关键词仍可能放行低余弦资料，报告保留该条件，不能声称提高余弦就能排除它。
- 样本只留在面板，关闭后丢弃。角色、存档、来源、设置或接口/模型变化后旧样本失效，需要重新试查。可取消采样；参数、原文和原检索诊断不会被试查覆盖。
- 本批不添加模型自动切换、真实API批量基准、永久标签库或自动应用阈值。用户实际点击采样会请求已配置的嵌入接口，勾选专用重排会额外请求该接口；本轮验证均用模拟接口。

### V12：只清理当前独立索引的失效分块

- 入口：记忆管理“设置 → 独立索引缓存 → 当前独立索引的失效分块”。先预览，再点击清理并确认；“只检索已有索引”模式也可操作，不要求临时发聊天请求或重建向量。
- 预览分开统计来源删除/撤销/不可读、正文或分块设置变化、无效向量、维度不符和孤立向量。分块引用数与物理向量数分别显示；同一物理向量可能被多处引用，不能把两者混算。
- 复用现有来源权限、清洗及分块计划，保留仍匹配的完整向量；不因来源快照整体变化就删除全部缓存。大小为数值数组的估算，不是磁盘用量或精确可回收空间。
- 预览时固定模型/存档/来源和缓存修订版本；执行在独立索引数据库内用现有事务和版本比较写入。其他页面更新、关闭面板、切档、改来源或改模型后拒绝旧计划；保存失败整体回滚，不清掉较新的块。
- 仅清理当前独立索引，原聊天、日记、待审稿、其他模型/存档缓存和备份兼容镜像不改。读取权限仍按原逻辑即时复核；原有旧空间整份删除继续保留。清理后刷新缓存清单、清掉当前页面的短时检索结果/旧诊断，再检索时重新读取。
- 本批没有承诺清除各页面已经载入的内存、浏览器实际回收空间或顺带删除备份里的旧镜像；跨数据库的原数据/便携镜像保存不混进此次派生清理事务。
