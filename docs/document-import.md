# 文档、人设、世界书与表情包

## 人设与展开编辑

人设输入框上方的 **导入 DOCX / TXT** 支持角色人设、用户人设和群成员人设。解析后先显示编辑草稿，可选择替换或追加；点击“应用”后按原页面方式保存。联系人里的角色卡导入入口也可直接用 DOCX/TXT 创建角色。

人设、世界书、美化 CSS、小组件 HTML/JS 等长文本旁提供 **展开编辑 / 查找替换**。支持区分大小写、上一个/下一个、单次/全部替换；搜索按文字匹配，替换内容中的 $& 等字符保持原样。桌面端可用 Ctrl/Cmd+F、Ctrl/Cmd+H 打开查找，Enter/Shift+Enter 切换匹配。取消会放弃草稿。

DOCX 仅提取文字，格式不作为聊天提示词保存；旧版 .doc 请另存为 .docx。TXT 支持 UTF-8、带 BOM 的 UTF-16，以及 GB18030。文件上限 20MB，DOCX 解压内容上限 80MB，避免大文件卡住手机。

## 世界书导入和触发

世界书 → 右上角新建菜单 → **导入 DOCX / TXT / JSON**。DOCX/TXT 导入为一个可编辑条目，JSON 支持 SillyTavern entries 对象、角色卡的 character_book.entries、条目数组，以及本项目条目。导入后进入新文件夹，需到聊天设置中绑定。

“酒馆进阶设置”提供：

- 常驻或关键词触发、启用/停用。
- 主要关键词任一命中；可选筛选支持 AND ANY、AND ALL、NOT ANY、NOT ALL。
- 扫描最近多少条消息、大小写、完整单词匹配；关键词还可使用 /正则/flags。
- 0–100% 触发概率，0 为不触发；每次聊天请求只判断一次。
- 插入顺序，数值越小越靠前。原有“注入深度”本来用于排序，现显示为“插入顺序”，保留旧数据含义。
- **聊天中**：额外指定聊天深度和 system/user/assistant 身份。深度 0 在最后一条上下文消息之后，1 在最后一条之前，超出上下文长度时放在最前。按实际进入请求的消息数计数，不是界面的所有历史楼层。

前/后/破限/聊天规范继续使用本项目已有插入区域。聊天深度适用于文字私聊和群聊；通话和日记使用各自原有的世界书区域并遵守启用、触发、顺序与概率。记忆隐藏的原楼层不参与普通聊天关键词扫描。大总结等已有提示词正文不变。

SillyTavern JSON 的 0/1/4 分别对应前、后、聊天中。示例对话、作者注释和 Outlet 等无法准确对应本项目结构的位置，会提示并停用对应条目，原始字段保存在 importSource；可手动编辑选择本项目位置后启用。当前不执行酒馆脚本、递归触发、向量检索、包含组和定时效果，不等同于完整酒馆运行时。

Gemini 不提供位于聊天中间的 system 消息，因此此类内容以原位置的 [system] 文本插入；动态聊天记录占位符模式中的历史仍转换成原位置的文字。OpenAI 兼容接口按所选身份插入消息。

规则参考：SillyTavern 官方 [World Info 文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)。

## 表情包文档和联想

聊天 → 表情面板 → 管理菜单 → 批量导入 → **从 DOCX / TXT 导入表情**。

TXT 或 DOCX 中每行可写：

~~~text
开心|哈哈,好耶|小猫举手欢呼，表示开心:https://example.com/happy.png
晚安|睡觉,困了|小猫盖被子:https://example.com/sleep.gif
~~~

“名称:URL”旧格式仍支持。DOCX 也可以嵌入图片，建议用表格：一格写“名称|关键词|画面说明”，同一行另一格放图片。导入预览可取消某张图、修改名称、关键词、说明及分组，确认后保存。每次最多 300 张。PNG/JPEG/GIF/WebP/BMP 支持嵌入；网络图片仍依赖原链接。

在聊天框输入匹配名称或关键词的文字后，输入框上方显示最多 8 个表情候选。点击直接发送表情，保留当前文字草稿。中文输入法组词期间不刷新候选；切换聊天、存档或进入多选会清空旧候选。

表情网格中点 **编辑** 可以修改关键词和画面说明，或点 **使用 API 识别当前图片**，调用支持视觉的模型生成说明。默认用主 API；可在 API 设置中启用副 API 的“表情图片识别”路由。识别由按钮发起，不会在打字或导入时自动调用收费 API。识别结果先留在编辑框，确认并保存后生效。

发送表情时会把已保存的画面说明随消息交给角色；聊天设置绑定某表情分组后，该组的图片说明也提供给角色参考，以原有表情名称格式选择发送。仅有名称而未填说明的旧表情仍按旧行为使用。识别质量取决于所选视觉模型；跨域受限的图片可先本地上传再识别。
