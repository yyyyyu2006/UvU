# 2026-11-03 通知、备份与记忆检索优化

## 实际修改

1. 通知跳转：openChatRoom 在确认聊天存在后统一设置 ID 和类型，再渲染消息和回复控制；私聊、群聊及自定义气泡继续使用原入口。修复只改标题、实际发送对象仍为旧聊天的问题。
2. 手动记忆回滚：捕获来源存档及本次新增、编辑、合并标记。保存失败时同时修复活动数据和来源存档；保留其后新增的记忆和已再次编辑的内容。
3. 普通联系人元数据：联系人列表、绑定标签、选择角色和聊天列表中的名字、头像、预览通过 DOM 属性／textContent 赋值。保留既有类名和布局，不对聊天气泡 HTML 或用户 CSS 做全局清洗。
4. 大备份：Worker 读取、解压并解析 JSON／EE，只向页面传回勾选模块；兼容原始 JSON 和 modules 包装。增加大文件提示、错误及超时处理。后台解析仍需要完整 JSON 字符串和对象，不能消除内存峰值；解压后超过 512 MB 拒绝继续，建议分类导出。不支持 Worker 时只接受不超过 8 MB 的 JSON／解压后 EE，明确提示升级或拆分。
5. 可选大数据迁移：数据管理新增“相册／工坊／阅读数据”，默认不选，独立导入导出。包含当前及已存档 gallery、characterPhotos、workshopHistory、workshopVibeGroups、reader_books、reader_chapters、reader_comments。字体继续走原字体分类。缓存表读取放在同一只读事务；导入时选中表按快照替换，与受影响角色／群聊一起原子提交，失败不改变内存数据。单独导入相册需要对应角色和存档已经存在；普通七类与新增类别可一起导入。未勾选缓存不写缓存表。老版可继续读取原七类，但不会自动认识新增 mediaCache 模块。
6. 大库比较：历史和日记逐条指纹代替整库一次序列化，降低单次临时字符串规模；索引比较只比较片段键、范围和复用的向量引用，不再序列化全部浮点向量。仍扫描历史，仍检查原地编辑、切档、配置变更及迟到结果，未声称达到常数开销或保证真机帧率。
7. 可选模型适配：查询前缀、文档前缀和支持模型的 Gemini 检索任务类型分别配置，默认空／模型默认，不改变旧请求。文档适配改变后重建受影响嵌入；仅改查询前缀不重建文档。Gemini embedding 2 不支持 taskType，选错时请求前明确报错；可改用模型默认及其要求的文字指令。没有改变原聊天或总结提示词。

## 通知行为与边界

- 站内始终最多一条，新消息覆盖旧消息；手指向上超过 32px 且以垂直方向为主时关闭。横滑、触摸取消不误开聊天；轻点与键盘操作可正常打开目标聊天。
- API 设置新增“系统消息通知”。只有用户手动开启才申请权限，权限和开关仅保留在当前设备；不随备份迁移系统权限。
- 页面后台仍有执行机会时，已授权的浏览器通过 Service Worker showNotification 显示系统通知。相同 tag 更新同一条；点击聚焦本站页面并打开对应私聊／群聊，页面不存在则新开并通过编码后的目标恢复导航。
- 当前是 GitHub Pages 静态前端。浏览器关闭、页面冻结、系统暂停后，不能继续靠网页定时器调用 AI 或保证实时到达。此轮没有搭建后端、保存服务端密钥或宣称实现关闭后的推送。
- 真正关闭后推送需要独立服务：管理 Push 订阅和 VAPID、接收／调度消息事件、调用推送服务，前端 Service Worker 接收 push。还需明确消息生成在哪运行、凭据存储、费用及隐私边界，再实施服务端部分。
- iOS／iPadOS Web Push 的官方前提是支持版本、加入主屏幕及用户操作授权；普通浏览器标签和不同 WebView 能力不同，以设备检测结果为准。系统通知中心、横幅、声音及专注模式仍由系统设置控制。

## 额外扫描清单（仅记录）

1. 工坊角色列表等其他旧界面仍有元数据 HTML 模板拼接，此次只覆盖审计列出的联系人／聊天列表入口；可继续逐处 DOM 化，不能全局禁用消息 HTML。
2. 导出仍在页面 JSON.stringify，超大导出可能短暂阻塞；Worker 导入也非流式 JSON 解析，仍受手机可用内存限制。后续可评估分卷及增量格式，需明确旧版兼容策略。
3. 向量索引保存失败的旧 catch 只恢复活动对象上的索引，跨存档快照回滚仍可进一步完善；索引可重建，但失败时的存档一致性值得补充专项检查。
4. 全历史过滤、指纹和候选提取仍为线性扫描；本轮减少字符串和向量序列化，未增加全局变更追踪。更大性能优化需要覆盖所有编辑入口后才可采用版本号。
5. 真机键盘、自定义美化、不同通知权限策略及原生 WebView 仍待设备验证；后台存活和系统横幅不能由网页保证。
